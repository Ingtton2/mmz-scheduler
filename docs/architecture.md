# 기술 스택 & 프로젝트 구조 (1단계 산출물)

이 문서는 "개발 지식이 거의 없는 사장님" 기준으로 최대한 쉽게 설명합니다.

---

## 1. 이 앱이 왜 "서버"가 필요한가?

지금까지 있던 `index.html` 한 파일짜리 방식으로는 이 스펙을 만들 수 없습니다. 이유:

| 스펙 요구사항 | 왜 서버가 필요한가 |
|---|---|
| 자동배치 엔진 (OR-Tools) | OR-Tools는 **파이썬**에서 도는 계산 라이브러리입니다. 브라우저 안에서는 못 돌립니다. |
| QR 코드로 스케줄 공유 | 직원이 QR을 찍으면 `앱주소/schedule/abc123` 같은 주소로 들어옵니다. 그 주소를 받아서 스케줄을 돌려줄 "무언가"(=서버)가 항상 켜져 있어야 합니다. |
| 직원이 연차를 미리 신청 | 신청 내용을 어딘가에 **저장**해야 합니다. → 데이터베이스 필요 |
| 나중에 여러 매장 확장 | 매장·직원·스케줄 데이터를 구조적으로 저장해둬야 합니다. |

그래서 이 프로젝트는 **두 덩어리**로 나뉩니다:

```
[ 프론트엔드 ]  ←→  [ 백엔드 (서버) ]  ←→  [ 데이터베이스 ]
 화면·버튼·표          계산·저장·QR발급         실제 데이터 보관
 (브라우저에서 돎)      (파이썬으로 돎)          (파일 하나로 시작)
```

## 2. 선택한 기술 스택

### 2.1 백엔드 (서버) — 파이썬

| 도구 | 한 줄 설명 | 왜 이걸 골랐나 |
|---|---|---|
| **Python 3.13** | 프로그래밍 언어 | 스펙이 권장한 OR-Tools가 파이썬 라이브러리라서. 이미 설치돼 있음. |
| **FastAPI** | "웹 서버"를 쉽게 만들어주는 틀 | 코드가 짧고, 자동으로 API 설명서(테스트 화면)를 만들어줌. 초보자 학습자료가 많음. |
| **Uvicorn** | FastAPI 앱을 실제로 켜주는 실행기 | FastAPI의 표준 짝꿍. |
| **Google OR-Tools** | 자동배치(제약 최적화) 계산 엔진 | **스펙이 직접 지목한 라이브러리.** 무료·오픈소스. 연차/인원/포지션/공정성 규칙을 "조건"으로 넣으면 최적 스케줄을 계산. |
| **SQLModel** | 파이썬 코드로 데이터베이스 표(테이블)를 다루게 해줌 | SQLite로 시작했다가 나중에 PostgreSQL로 갈아탈 때 코드 수정이 적음. |
| **SQLite** | 파일 1개짜리 데이터베이스 | 설치·설정이 전혀 필요 없음. `app.db` 파일 하나에 다 저장됨. 나중에 매장이 여러 개로 커지면 PostgreSQL로 교체. |
| **qrcode** | QR 코드 이미지 생성 | 스케줄 공유 URL을 QR 이미지로 변환. |

### 2.2 프론트엔드 (화면) — 자바스크립트

| 도구 | 한 줄 설명 | 왜 이걸 골랐나 |
|---|---|---|
| **React** | 버튼·표·달력 같은 화면 조각을 만드는 틀 | 스케줄 표를 셀 클릭·드래그로 수정하는 화면(스펙 6.1)은 React 같은 도구가 훨씬 수월함. |
| **Vite** | 개발 중 화면을 즉시 새로고침해주는 도구 + 배포용 빌드 도구 | React의 사실상 표준 짝꿍. 빠름. |
| **TypeScript** | 자바스크립트 + 오타·실수 잡아주는 기능 | 초반에 버그를 덜 만들게 해줌. |
| **Tailwind CSS** | 미리 만들어진 디자인 부품 모음 | CSS를 길게 안 써도 깔끔한 화면이 나옴. |
| **React Router** | 주소별로 다른 화면 보여주기 | `/admin`(사장님용), `/schedule/:code`(직원 조회용) 구분. |

### 2.3 나중에 (2단계 이후) 필요해질 것

- **배포**: 지금은 내 컴퓨터에서만 돌지만, 직원이 QR로 접속하려면 인터넷에 올려야 함. (Fly.io, Railway, Render 등 — 무료 등급 존재)
- **PostgreSQL**: 매장이 여러 개가 되면 SQLite → PostgreSQL 교체.

## 3. 폴더 구조

```
mmz-scheduler/
├── README.md                     ← 실행 방법
├── restaurant_schedule_app_spec.md  ← 원본 스펙 (건드리지 않음)
├── docs/
│   └── architecture.md           ← 지금 이 문서
│
├── backend/                      ← 파이썬 서버
│   ├── requirements.txt          ← 서버가 쓰는 라이브러리 목록
│   ├── .env.example              ← 설정값 예시 (비밀번호 등)
│   └── app/
│       ├── main.py               ← 서버 시작점
│       ├── config.py             ← 설정 읽기
│       ├── database.py           ← 데이터베이스 연결
│       ├── models/               ← 데이터 표 정의 (직원, 스케줄, 연차, 근무코드…)
│       ├── schemas/              ← 주고받는 데이터 형태 정의
│       ├── api/                  ← 주소(엔드포인트) 정의 — 화면이 여기로 요청함
│       ├── scheduler/            ← ⭐ 자동배치 엔진 (OR-Tools). 이 앱의 핵심
│       └── services/             ← QR 생성, 연차 계산 등 부가 로직
│   └── tests/                    ← 자동 테스트
│
└── frontend/                     ← 화면 (React)
    ├── package.json              ← 화면이 쓰는 라이브러리 목록
    ├── index.html                ← 껍데기 HTML 1개
    ├── vite.config.ts            ← Vite 설정
    └── src/
        ├── main.tsx              ← 화면 시작점
        ├── App.tsx               ← 최상위 화면 + 주소 분기
        ├── pages/                ← 페이지 단위 화면 (사장님용 / 직원 조회용)
        ├── components/           ← 재사용 화면 조각 (표, 버튼, 달력…)
        ├── api/                  ← 백엔드에 요청 보내는 코드
        └── styles/               ← 스타일
```

**핵심만 기억하면**: `backend/app/scheduler/` = 자동배치 두뇌, 나머지는 그걸 둘러싼 화면·저장·전달 장치.

## 4. 데이터 모델 밑그림 (표 목록)

스펙 2·3·4·10장을 반영. **모든 표에 `store_id`를 넣어** 나중에 여러 매장으로 확장 가능하게 함 (스펙 10.1).

| 표 이름 | 담는 내용 | 주요 칸 |
|---|---|---|
| `store` | 매장 | 이름, 생성일 |
| `staff` | 직원 | store_id, 이름, 고용형태(정직원/파트타임 — 사장님은 없음), 포지션(홀/주방/겸직), 역할(직원/사장님), 근무가능요일(0~6, 기본 전체), 고정근무여부 · 사장님 A(홀만)=포지션 홀, B(홀+주방)=포지션 겸직 · 연차정보(leave_balance)는 정직원만 |
| `work_code` | 근무 코드 (매장별 커스텀) | store_id, 코드(O/M/C…), 이름, 시작시간, 종료시간, 색상 |
| `leave_balance` | 직원 연차 정보 | staff_id, 기본휴무, 전월잔여연차, 전월발생연차, 합연차, 연차사용, 잔여연차 |
| `leave_request` | 직원 연차 신청 | staff_id, 날짜, 상태(신청/확정) |
| `staffing_requirement` | 요일·시간대별 필요 인원 | store_id, 요일, 시간대(런치/디너), 포지션, 최소인원 |
| `schedule` | 완성된 월 스케줄 1개 | store_id, 연월, 상태(작성중/확정), 공유코드(QR용 고유문자열) |
| `schedule_entry` | 스케줄 한 칸 (직원×날짜) | schedule_id, staff_id, 날짜, 근무코드 |

> 이 표들은 2단계(뼈대 확정 후)에서 실제 코드로 만듭니다. 지금은 폴더와 빈 파일만 잡아둔 상태입니다.

## 5. 실행 흐름 미리보기 (2단계에서 진행)

1. `backend/` 에서 파이썬 가상환경 만들고 라이브러리 설치 → 서버 켜기 (`http://localhost:8000`)
2. `frontend/` 에서 `npm install` → 화면 켜기 (`http://localhost:5173`)
3. 브라우저에서 화면을 보면서 기능을 하나씩 붙여나감

자세한 명령어는 `README.md` 참고.
